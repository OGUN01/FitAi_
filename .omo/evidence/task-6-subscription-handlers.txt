## Handler Functions
- handleCreateSubscription: Validates body, looks up plan from subscription_plans table,
  creates Razorpay subscription via razorpayFetch(), saves to Supabase, returns subscription_id + key_id
- handleVerifyPayment: Validates razorpay_payment_id + razorpay_subscription_id + razorpay_signature,
  verifies signature using verifyPaymentSignature(), updates subscription status to 'authenticated'
- handleWebhook: Reads raw body via c.req.text(), verifies webhook signature, idempotency check
  via webhook_events table, processes 7 event types, ALWAYS returns HTTP 200
- handleGetSubscriptionStatus: Queries subscriptions JOIN subscription_plans, returns free tier default

## Key Design Decisions
- Webhook uses c.req.text() for raw body (NOT re-serialized JSON) to preserve signature integrity
- Webhook always returns 200 even on internal errors (prevents Razorpay retry storms / endpoint disable)
- `satisfies SubscriptionStatus` used for type-safe string literals without widening
- Grace period: 'pending' status treated as active access via isAccessGrantingStatus()
- Razorpay plan IDs looked up from subscription_plans table (not hardcoded)
- webhook_events table used for idempotency (graceful try/catch if table missing)
- No `as any` or `@ts-ignore` used
- No console.log in production paths
